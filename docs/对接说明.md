# 对接说明

## 0. 简介

目前有两种对接方式：

| 路线 | 需要开发什么 | 能力 | 适合场景 |
| ---- | ---- | ---- | ---- |
| **HTTP 转发（推荐）** | 一个 HTTP 接口（如 Java Spring Boot Controller） | 接收主机事件报告 + 远程布撤防（httprelay 1.0.0 起） | 绝大多数项目 |
| TCP 直连 | 自行开发 TCP Server（需实现协议解析、心跳、ACK 应答、重传处理） | 接收事件 + 完整远程控制 | 特殊控制需求（如索要防区信息、定时器管理等） |

推荐 HTTP 转发路线：使用本项目提供的 `httprelay` 程序接收主机 `TCP` 连接并转发事件到你的 `HTTP` 服务器，你只需开发一个 `HTTP` 接口；需要布撤防等控制能力时（httprelay 1.0.0 起），为 `httprelay` 增加一个控制参数即可。本文第 1~6 章围绕此路线展开，第 11 章为常见问题；特殊控制需求请看第 12 章。`httprelay` 拥有独立版本号，`httprelay --version` 可查询。

## 1. 体系结构

```mermaid
flowchart LR
    D[探测器<br/>门磁/红外/紧急按钮等] -- 无线 --> M[报警主机]
    M -- TCP 安定宝协议 --> R[httprelay<br/>运行在你的服务器上]
    R -- HTTP POST JSON --> S[你的 HTTP 服务器]
```

说明：

- 探测器与主机之间无线通信，无需你关心；
- 主机作为 `TCP` 客户端主动连接 `httprelay`，协议解析、心跳应答（`ACK`）、事件提取全部由 `httprelay` 完成；
- 你的 `HTTP` 服务器只需按第 5 章的规格接收 `JSON` 事件即可。

## 2. 准备工作

1. **确认主机的网络形态**，决定 `httprelay` 的部署位置：

   - 插 `SIM` 卡的主机（GPRS / 4G / 物联卡 / NB）：`httprelay` 必须运行在**公网**服务器上（有公网 IP 或域名）；
   - 网线主机、WiFi 主机、网络模块+工程主机：可以运行在主机可访问的**内网**环境，前提是先在公网环境下通过手机 `APP` 配置好直连接警中心信息、配对好探测器等。

2. **获取主机账号（`acct`）**：每台主机机身上有标签，上面印有账号及账号二维码、出厂日期、型号等信息。账号是事件的唯一主机标识，用于建立 `acct` 与你的业务对象（站点、资产等）的映射关系。

3. **下载 `httprelay`**：从 [releases](https://github.com/captainwong/ademco_hb/releases) 下载压缩包，`examples` 内含 Windows x86/x64 版 `httprelay.exe` 及其依赖 `libcurl.dll`，另有直连型主机模拟器等测试工具。Linux/macOS 下需自行编译：安装 `libuv, libcurl` 的 `dev` 包后，在 `examples/httprelay` 目录执行 `build.sh`。

## 3. 部署 httprelay

```bash
./httprelay 12345 http://your-http-server.com:8080/ademco
```

`httprelay` 将：

- 监听 `TCP` 端口 `12345` —— **这个端口是给报警主机连接用的**，配置主机时填它；
- 收到主机事件后，向 `http://your-http-server.com:8080/ademco` 发送 `HTTP POST` 请求 —— **这个 URI 是你的 HTTP 服务器接收事件的接口地址**。

两个地址互不相干，一个是 `TCP`、一个是 `HTTP`，请勿混淆。

## 4. 配置报警主机

使用手机 `APP` 配置主机（配置接警中心 `IP`、端口时，在手机 `APP` 内设置界面找到 **标准接警中心**），将直连接警中心的地址 / 端口填写为 `httprelay` 所在服务器的 `IP` / 域名与 `TCP` 监听端口。网络模块 + 工程主机也可以使用[网络模块配置工具](https://net-mod-config-tool-1251421422.cos.ap-chengdu.myqcloud.com/%E7%BD%91%E7%BB%9C%E6%A8%A1%E5%9D%97%E6%89%B9%E9%87%8F%E9%85%8D%E7%BD%AE%E5%B7%A5%E5%85%B7v1.8.2.195.exe)进行配置。

主机开机后主动连接 `httprelay`，连接成功后报告一次状态（及主机类型），此后定时发送心跳包，`httprelay` 自动应答，无需干预。

## 5. HTTP 回调接口规格

### 5.1 请求格式

本节规格适用于**本仓库的 `httprelay`**（github 下载或自行编译）。经商用接警中心软件等渠道分发的定制转发器，转发格式可能不同，请以其配套说明为准。

- 方法：`POST`，`Content-Type: application/json`，body 为 `JSON` 对象；
- 请求地址即 `httprelay` 启动参数中的 URI，**无任何 query 参数**；
- 每个事件一次请求。

字段说明：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `acct` | string | 主机账号，来自机身标签 |
| `ademco_event` | number | 事件码，含义见[事件码表](./README.md#三事件码) |
| `zone` | number | 防区号。`0` 表示主机自身事件（布防、撤防、防拆等）；`1~999` 表示对应防区的事件 |
| `gg` | number | 一般为 `0`；三区段主机为 `1~3`（区段号），详见[协议文档](./README.md)第 4.1 节 |
| `timestamp` | number | 事件时间戳，`Unix` epoch 秒。注意：主机使用 `UTC` 时间，且 `httprelay` 按其运行环境的本地时区换算，跨时区部署时请先实际验证偏移 |

### 5.2 请求示例

```json
{"acct":"861234567890","ademco_event":3400,"zone":0,"gg":0,"timestamp":1763893209}
```

含义：账号为 `861234567890` 的主机于 `timestamp` 时刻上报了 `3400`（离家布防）事件。

```json
{"acct":"861234567891","ademco_event":1130,"zone":80,"gg":0,"timestamp":1763893459}
```

含义：账号为 `861234567891` 的主机的 `80` 防区触发了 `1130`（盗警）。

### 5.3 上线与掉线事件（ONLINE / OFFLINE）

`1946`（主机上线）与 `1944`（主机断线）**不是主机上报的协议事件，而是 `httprelay` 合成的连接状态事件**：

- 主机 `TCP` 连接建立并发来第一个数据包时，`httprelay` 发送 `ademco_event=1946`；
- `TCP` 连接断开（主机重启、断电、网络中断等）时，发送 `ademco_event=1944`。

除 `1944`/`1946` 外，其余事件均来自主机上报。心跳包不会转发，请以 `1946`/`1944` 维护主机的在线状态。注意：主机掉电且恰好处于网络故障等极端情况下可能收不到 `1944`，如对掉线检测有严格要求，建议在你的服务器上对 `1946` 之后长时间无任何事件的主机做超时判断。

### 5.4 应答要求

`httprelay` 不检查响应内容，但请求超时时间为 **3 秒**，你的接口应在 3 秒内返回（返回什么状态码、什么 body 均可）。请不要在回调处理中同步执行耗时操作（如推送、短信），收到后快速落库/入队异步处理。

### 5.5 事件可靠性语义

- **事件可能重复（at-least-once）**：若你的服务器响应超时，主机会因未及时收到 `ACK` 而重发事件，`httprelay` 将再次转发。建议按 `(acct, ademco_event, zone, timestamp)` 做幂等去重；
- **事件可能丢失**：`httprelay` 不缓存、不重试转发，若你的服务器宕机期间主机上报了事件，事件将丢失（主机侧因 `httprelay` 已代答 `ACK` 而认为送达）。请保证接收服务的可用性，或将事件先写入可靠队列。

### 5.6 安全注意事项

`httprelay` 转发请求不带任何鉴权信息。建议：

- 使用 `HTTPS` URI 并在路径中加入随机串（如 `/ademco/5f3a9c/`）作为简易鉴权；
- 在你的 `Web` 服务器（nginx 等）上限制来源 `IP` 为 `httprelay` 所在服务器。

## 6. 远程控制（布撤防，httprelay 1.0.0 起）

`httprelay` 1.0.0 起内置远程控制接口，可对**在线主机**下发布防、撤防命令。与事件接收一样走 `HTTP`，无需 `TCP` 直连。

### 6.1 启用

在原有启动参数后追加选项（支持 `--key=value` 与 `--key value` 两种写法）：

```bash
./httprelay 12345 http://your-server:8080/ademco --control_port=8081
```

| 选项 | 默认值 | 说明 |
| ---- | ---- | ---- |
| `--control_port` | 未启用 | 控制接口监听端口，不传则不启动控制功能（与旧版行为完全一致） |
| `--listen_addr` | `127.0.0.1` | 控制接口监听地址。仅本机访问保持默认；内网其他机器访问设为 `0.0.0.0` |
| `--token` | 无鉴权 | 控制请求须携带的 `Bearer` token，建议公网部署时必配，可用 `openssl rand -hex 16` 生成 |

```bash
# 公网部署完整示例
./httprelay 12345 http://your-server:8080/ademco \
    --control_port=8081 --listen_addr=0.0.0.0 --token=$(openssl rand -hex 16)
```

### 6.2 控制请求规格

- `POST /control`，`Content-Type: application/json`；
- 配置了 `token` 时须携带请求头 `Authorization: Bearer <token>`；
- 请求体字段：

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `acct` | 是 | 目标主机账号 |
| `ademco_event` | 是 | 仅允许 `3400`（离家布防）、`3456`（留守布防）、`1400`（撤防），其他值被拒绝。**`3456` 依主机型号而定**：部分主机（如 5050 网线主机）不支持留守布防，会回应 `NAK` 且不执行 |
| `gg` | 否 | 三区段主机区段号 `1~3`，默认 `0`（整机） |
| `zone` | 否 | 操作源，默认 `99`（直连接警中心）。自定义后主机的状态回报会原样回显该值，用于关联你发起的命令 |
| `password` | 撤防必填 | 主机密码（出厂默认 `123456`，建议修改），布防不需要 |

```json
{"acct":"861234567890","ademco_event":1400,"zone":99,"password":"123456"}
```

### 6.3 应答格式

统一返回 `HTTP 200`，结果以 body 中的 `code` 字段表达（调用方无需处理非 2xx 异常）：

| code | 含义 |
| ---- | ---- |
| `{"code":0,"msg":"ok"}` | 命令已写入主机连接 |
| `{"code":1,"msg":"bad request..."}` | 请求不合法（JSON/字段/事件码不在白名单/撤防缺合法密码） |
| `{"code":2,"msg":"unauthorized"}` | token 缺失或错误 |
| `{"code":3,"msg":"machine offline"}` | 目标主机当前无 TCP 连接 |

控制为 **fire-and-forget** 语义：应答只表示命令已下发，不等待主机执行。

### 6.4 执行结果回执

主机的执行结果通过第 5 章的事件回调返回：

- 执行成功：主机上报对应状态事件（`3400`/`3456`/`1400`），**`zone` 字段回显你发起控制时传的 `zone`**（默认 99），据此可关联命令与结果；
- 撤防密码错误：主机上报 `1701`（撤防密码错误）；个别型号不回应；
- 超时未收到状态事件（如按 10 秒计）应视为未执行，可重发。

### 6.5 Java 控制示例（Spring Boot + RestTemplate）

```java
record ControlReq(String acct, int ademco_event, int zone, String password) {}

public boolean disarm(String acct, String password) {
    var headers = new HttpHeaders();
    headers.setContentType(MediaType.APPLICATION_JSON);
    headers.setBearerAuth(token); // httprelay 启动时配置的 token
    var req = new ControlReq(acct, 1400, 99, password);
    var resp = restTemplate.postForObject(
            "http://relay-host:8081/control", new HttpEntity<>(req, headers), String.class);
    return resp != null && resp.contains("\"code\":0");  // 建议解析为 DTO 判断
}
```

### 6.6 安全建议

- `--token` 仅防伪造，不加密传输。控制端口暴露公网时，务必前置 `nginx`/`caddy` 终结 `HTTPS`（`httprelay` 的控制端口保持 `127.0.0.1`，由反代转发），并限制来源 `IP`；
- 撤防密码通过请求体明文传给 `httprelay`，公网裸 `HTTP` 下会被嗅探——同上，用 `HTTPS`；
- 主机出厂密码为 `123456`，接入后建议尽快通过主机 `APP` 修改。

## 8. 已知限制（HTTP 转发路线）

- `xdata` 段不转发。因此 `1799`（信号强度变化）、`1708`（电源状态）等通过 `xdata` 携带数值的事件，转发后只有事件码、没有具体数值；
- 不转发主机的安定宝 `ID`（`ademco_id`），主机以 `acct` 唯一标识；
- 仅能接收事件与布撤防控制，无法使用索要防区信息、定时器管理等高级控制。有此需求请走 TCP 直连路线（第 12 章）。

## 9. Java 接收示例（Spring Boot）

```java
@RestController
public class AdemcoController {

    record AdemcoEvent(String acct, int ademco_event, int zone, int gg, long timestamp) {}

    @PostMapping("/ademco")
    public void onEvent(@RequestBody AdemcoEvent event) {
        // 快速落库/入队，勿在此做耗时操作（应答须在 3 秒内）
        System.out.printf("主机 %s 于 %d 上报事件 %d, 防区 %d%n",
                event.acct(), event.timestamp(), event.ademco_event(), event.zone());
        // 按事件码分发处理，如:
        // switch (event.ademco_event()) { case 1130 -> handleBurglar(event); ... }
    }
}
```

注意：Java 16 前无 record，可用普通 POJO + Jackson 注解代替；字段名与 JSON 完全一致即可。

1. **无主机时**：从 releases 下载 `直连型主机模拟器`，将模拟器的接警中心指向 `httprelay`，即可模拟布撤防、防区报警等事件；

## 11. 常见问题（FAQ）

以下问题来自多年对接支持的实际高频提问。

**Q1：主机能不能直接向我服务器发 HTTP 请求？**

不能。主机只有 `TCP` 长连接能力，这正是 `httprelay` 存在的意义——由它完成 `TCP` 接入并转为 `HTTP` 转发。

**Q2：收不到主机连接 / 一直没事件，怎么排查？**

按顺序自检：

1. 安定宝 `ID` 是否已在 `APP` 标准中心里设置（非 `0`，多台主机各自不同，如从 `000001` 递增）；
2. `APP` 标准中心的 `IP`/域名、端口是否为 `httprelay` 所在服务器及其 `TCP` 监听端口，配置后是否保存并重连；
3. 插卡主机是否公网可达（云服务器或端口映射）；云服务器安全组 / 防火墙是否放行该 `TCP` 端口；
4. 在任意 `PC` 上用 `telnet 服务器 端口` 或 `nc -vvv 服务器 端口` 验证端口可达；
5. 仍不通时在服务器上 `tcpdump tcp port 端口`（或 `wireshark`）看有无主机的 `SYN`，有 `SYN` 无数据多为服务器侧问题，无 `SYN` 多为主机侧配置 / 网络问题。

**Q3：为什么收不到信号强度（1799）等事件？**

事件是否上报依主机型号而定（参见[主机类型对照表](./README.md#_恒博主机类型对照表_)的信号强度列）。收不到说明该型号不支持，属正常现象。另注意 `HTTP` 转发路线不转发 `xdata`，信号强度的具体数值也拿不到（见第 8 章）。

**Q4：报警触发后，什么时候算「报警结束」？**

分两层看：

- 警情类（盗警等）：多数主机不产生警情结束事件，**撤防（`1400`）即消警、消音**；
- 开关量/对射类探测器（电子围栏、周界等）：只有「报警」报文、没有「恢复」报文，是产品机制不是故障。平台侧标准做法：**收到报警将防区置为报警态，超时（如 15 秒）未再收到报警则自动恢复**，或以收到撤防事件统一恢复。

防区异常类事件（掉电、低电、失联等）则有对应的恢复事件（`3xxx`），详见[事件码表](./README.md#三事件码)。

**Q5：一次报警为什么收到好几条？**

未撤防状态下，探测器在报警持续期间会周期性重发无线报警信号（对射类典型为三分钟内持续提醒），主机每收到一条就上报一条（实测可达数秒一条），属正常机制、不是故障。处置建议：平台按 `(acct, zone, 事件码)` 判定为同一警情（首条触发告警、后续视为持续），或撤防即停——撤防后主机不再处理普通匪警防区的报警信号。注意与 5.5 节的「转发层重复」区分：这里是探测器端重发，那层是 `ACK` 超时重发，平台侧统一幂等即可。

**Q6：`acct` 为什么有的是 14 位数字、有的是 6 位？**

不同型号主机的 `#acct` 内容不同：插卡主机为手机号，无卡主机为出厂编号（机身标签的 14/15 位数字），部分型号直连时使用安定宝 `ID`，`WiFi` 主机使用 `MAC` 地址。以机身标签为准，解析时按字符串处理（14 位数字超出 `int32` 范围，按数字解析会溢出）。

**Q7：同一事件收到多次？**

见 5.5 节：`HTTP` 转发路线为 at-least-once 语义，请按 `(acct, ademco_event, zone, timestamp)` 幂等去重。

**Q8：心跳多久一次？多久没消息算掉线？掉线频繁怎么排查？**

心跳（`NULL` 包）间隔约 30 秒 ~ 2 分钟，因主机型号而异（如 5050 网线主机为 30 秒），可实测取平均。`httprelay` 不转发心跳，掉线以 `1944` 事件为准（见 5.3）。主机作为 `TCP` 客户端断线后会自动重连（失败退避最长 60 秒）并再发 `1946`。

掉线频繁时按模式定位：

- **多台主机同一时间集体掉线** → 优先查 `SIM` 卡流量是否到期（最常见）；
- **单台随机掉线、时断时续** → 查信号强度值（`1799` 事件，依型号而定）、更换 `GPRS` 天线位置；
- **WiFi / 无线网络主机** → 丢包概率高，尽量改用有线网络。

**Q9：主机时间与我的服务器差 8 小时？**

主机使用 `UTC` 时间，按需换算即可（见 5.1 节 `timestamp` 说明）。

**Q10：能对单个防区布撤防吗？**

普通主机布撤防的对象是整台主机，不能按防区操作；三区段主机可按区段（`gg=1~3`）布撤防。`httprelay` 1.0.0 起支持远程布撤防（见第 6 章）；索要防区信息等高级控制仍需 `TCP` 直连路线（第 12 章）。

**Q11：主机能远程重启吗？**

不能，如遇主机异常只能现场断电重启。

**Q12：控制返回 machine offline，但设备事件还在正常转发？**

`httprelay` 的控制索引仅包含当前 `TCP` 在线的主机。主机掉线重连期间（如网络抖动）、或刚收到 `1944` 断线事件后短时间内发起控制，会返回 offline。稍候重试即可。

## 12. 特殊控制需求？（TCP 直连路线）

`HTTP` 转发路线已支持布防、撤防等常用控制（见第 6 章）。但索要防区信息（防区表下载）、定时器管理、主机配置程序修改等完整协议能力不在 `httprelay` 范围内，需要此类能力时须自行开发 `TCP SERVER` 直接对接主机，协议详见[协议文档](./README.md)：

- 熟悉 `C/C++`：参考 `examples/server_demo` 源码；
- 其他语言：参考 [swig 绑定](../swig/README.md)（Java / C# / Node.js）。
