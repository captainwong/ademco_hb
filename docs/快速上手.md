# 快速上手：从零到收到第一条报警（15 分钟）

本教程面向第一次接触本项目的开发者，**不需要真实主机**，用模拟器即可全流程跑通。全程只需：一台 Windows 电脑、会打开命令行。

读完本教程你将完成并理解这条链路：

```mermaid
flowchart LR
    SIM[模拟器<br/>或真实主机] -- TCP --> R[httprelay<br/>命令行窗口常驻]
    R -- HTTP POST JSON --> S[你的接收端<br/>见对接说明]
```

`httprelay` 是**中间层**：它替你完成协议解析、心跳应答，把主机事件转成 `JSON` 推给你的服务器。它不是「装完就不用管」的软件，而是一个需要**一直运行**的命令行程序——理解这一点，下面所有步骤都会顺理成章。

各步骤的详细规格（接口字段、事件码、远程控制等）在[对接说明](./对接说明.md)，本教程只管把你带进门。

## 1. 下载与解压

从 [releases](https://github.com/captainwong/ademco_hb/releases) 下载最新版压缩包，解压 `examples.zip`，得到若干 `exe`。

## 2. 认识目录里的 exe（别跑错）

| 程序 | 用途 | 你现在要跑它吗 |
| ---- | ---- | ---- |
| `httprelay.exe` | 事件转发器，**对接的主角** | ✅ 是 |
| 直连型主机模拟器 | 模拟一台真实主机，测试用 | ✅ 是（没有真机时） |
| `server_demo.exe` | 演示用 TCP 接警中心（开发参考） | ❌ 不是它 |
| `AdemcoParser.exe` | 协议帧解析工具 | 暂时不用 |

> 曾有开发者把 `server_demo` 当成转发器跑了半天，发现「没有设置回调地址的地方」——记住：**要转发到 HTTP，跑的是 `httprelay.exe`**。

## 3. 启动 httprelay

**不要双击 exe**——双击会打印一行用法后立即关窗，什么都看不到。正确方式：

1. 在 `httprelay.exe` 所在目录的地址栏输入 `cmd` 回车（或 Shift+右键 →「在此处打开 PowerShell/命令窗口」）；
2. 执行（回调地址暂时填一个占位地址即可）：

```bat
httprelay.exe 12345 http://127.0.0.1:9999/cb
```

**此时你应看到**：

```
httprelay 1.0.0
tcp server listening on 0.0.0.0:12345
```

窗口停住不动是**正常的**——它在等主机连入。这个窗口关闭，转发也就停止了。

参数含义：`12345` 是给**主机连接**用的 TCP 端口；`http://...` 是事件要转发到的**你的服务器**地址（本教程先用占位地址）。

## 4. 没有主机？用模拟器发一条报警

双击运行「直连型主机模拟器」，在界面中把接警中心地址/端口配置为本机与 `12345`（即 `httprelay` 所在机器的 IP 和 TCP 端口），保存并连接。连接成功后模拟器会上报状态与类型，界面触发一次报警（或布防/撤防）。模拟器的详细用法见[模拟器使用说明](./模拟器使用说明.md)（examples 包内附 PDF 版）。

**此时你应看到**：`httprelay` 窗口开始滚动日志：

```
C:\x0AD3D90051"ADM-CID"0001R123ABCL456DEF#861234567890[#000001|1130 00 030]\x0D
```

- `C:` 开头 = 收到主机的协议帧（`C` = Client 主机方向）；
- `S:` 开头 = `httprelay` 回应主机的 `ACK`；
- `OUT:` 后跟 `JSON` = 正在转发给你的回调地址——**看到 `OUT` 与 `JSON`，链路即全通**。

## 5. 「窗口里的报错」正常吗？

模拟器连上但回调地址是占位地址时，会看到 `curl` 相关报错（连不上 `127.0.0.1:9999`）——**正常**：它表示转发已尝试、只是还没人接收。写好接收端（见[对接说明第 9 章](./对接说明.md) Java 示例）并把启动参数中的地址换成你的真实服务，`OUT` 的 `JSON` 就会出现在你的接口里：

```json
{"acct":"861234567890","ademco_event":1130,"zone":30,"gg":0,"timestamp":1763893459}
```

## 6. 配置要每次重新敲吗？——写个 start.bat

命令行参数**不会被程序记住**，重开窗口就要重新输入。解决：在同目录新建 `start.bat`（记事本编辑，保存为 ANSI/UTF-8 均可）：

```bat
@echo off
cd /d %~dp0
httprelay.exe 12345 http://你的服务器:8080/ademco --control_port=8081 --token=你的token
```

以后**双击 `start.bat`** 启动（注意：双击 bat 是正确姿势，双击 exe 不是）。改配置=改 bat 文件。

## 7. 常驻运行：服务器不该开着黑窗口

手动窗口方案只适合调试。正式部署用以下任一方式让 `httprelay` 随系统常驻（以 Windows 服务方式推荐用 [nssm](https://nssm.cc/)）：

```bat
nssm install httprelay "C:\path\to\httprelay.exe" "12345 http://你的服务器:8080/ademco --control_port=8081 --token=你的token"
nssm start httprelay
```

或使用任务计划程序设置「开机启动」。常驻后日志建议重定向到文件（nssm 可配置 `AppStdout`/`AppStderr`）。

## 8. 接入真实主机

真机到货后：手机 `APP` 中找到 **标准接警中心** 设置，填 `httprelay` 所在服务器的公网 `IP`/域名与 `TCP` 端口（即启动参数里的 `12345`，**不是** `--control_port`），主机开机后自动连接并上报，`ONLINE(1946)` 事件出现在你的接收端。

## 9. 进阶：远程布撤防初体验

启动时带了 `--control_port=8081 --token=...` 的话，模拟器在线时即可体验远程控制（`cmd` 中执行）：

```bat
curl -X POST http://127.0.0.1:8081/control -H "Content-Type: application/json" -H "Authorization: Bearer 你的token" -d "{\"acct\":\"861234567890\",\"ademco_event\":1400,\"password\":\"123456\"}"
```

**预期**：返回 `{"code":0,"msg":"ok"}`；`httprelay` 窗口出现 `S:`（下发命令）；模拟器执行撤防并回报状态事件（回执关联与字段详见[对接说明第 6 章](./对接说明.md)）。

## 10. 常见卡点

以下全部来自真实对接记录：

| 现象 | 原因与对策 |
| ---- | ---- |
| 双击 `httprelay.exe` 一闪而过 | 正常现象（打印用法即退出）。**必须命令行 / 双击 `start.bat` 运行** |
| 跑起来「没有反应」 | 正常，待命中。有主机事件才有日志 |
| 「需要一直运行吗？」 | 是，它是中间层，关掉就收不到消息。正式部署见第 7 章 |
| 「配置每次要重新敲？」 | 命令行参数不持久，用 `start.bat`（第 6 章）或注册服务（第 7 章） |
| 端口必须 `12345`？ | 可改，主机 `APP` 里配成一样即可 |
| 跑了 `server_demo` 找不到回调设置 | 跑错程序了，要 `httprelay.exe`（第 2 章） |
